# منصة مشوار للنقل الذكي (MISHWAR)
### Smart Ride-Hailing Platform for Yemen (Cars & Motorcycles)
**مرحلة المشروع:** PILOT VALIDATION & DEPLOYMENT READINESS (جاهز للتشغيل التجريبي)

---

## 🌟 نظرة عامة | Project Overview
**مشوار (MISHWAR)** هي منصة نقل ذكي متكاملة واحترافية مصممة خصيصاً لتلبية احتياجات السوق اليمني، تدعم طلب الرحلات عبر **الدراجات النارية (Motorcycles)** و **السيارات الخاصة (Cars)** مع هيكلية معمارية قابلة للتوسع إلى خدمات التوصيل وحسابات الشركات والمحافظات الأخرى (صنعاء، عدن، تعز، الحديدة، المكلا).

---

## 🏗️ مكونات المنصة | Platform Components
1. **تطبيق العميل (Customer App):** تطبيق هاتف مع محاكي ويب متزامن لطلب الرحلات، تتبع السائق، محادثة فورية، زر طوارئ SOS، ودفع نقدي (كاش) ومحفظة رقمية.
2. **تطبيق السائق / الكابتن (Driver App):** تطبيق كابتن مع نظام اتصال/عدم اتصال، استقبال الطلبات في 15 ثانية، ملاحة، وتفاصيل الأرباح والعمولة (10%).
3. **لوحة تحكم الإدارة (Admin Dashboard):** لوحة شاملة لإدارة السائقين والعملاء، خريطة حية لتتبع أسطول المركبات، محرك التسعير وتعديل العمولات، إدارة المناطق الجغرافية، وسجل الأمان وطوارئ SOS، وتبويب فحص واختبارات المحركات (Diagnostics).
4. **محرك التسعير (Pricing Engine):** احتساب الخوارزمية (أجرة البداية + الكيلومترات + الدقائق + الحد الأدنى للأجرة 1,800 للسيارات و 700 للدراجات + عمولة المنصة 10% + صافي أرباح الكابتن بالريال اليمني).
5. **محرك التوزيع الذكي (Smart Dispatch Engine):** مطابقة سريعة لأقرب كابتن متصل مع حماية من ازدواجية الطلبات ومؤقت زمني ذكي.
6. **دفتر الحركات المالية (Wallet Ledger):** سجل حركات مزدوج محاسبي لا يسمح بتعديل الأرصدة مباشرة بدون تسجيل `balanceBefore` و `balanceAfter` مع منع الخصم المزدوج (Idempotency).
7. **وضع العرض التجريبي المتزامن (Synchronized Demo Simulator):** تشغيل شاشتي العميل والسائق جنباً إلى جنب مع تحديث فوري للأحداث والموقع على الخريطة.

## 🚀 تشغيل وبناء المشروع | How to Run & Build

### 1. تشغيل المنصة ومحاكي الويب (Vite + React + TypeScript):
```bash
npm run dev
```
يعمل التطبيق على المنفذ `http://localhost:3000` ويتيح التبديل الفوري بين:
- **المحاكي المزدوج المتزامن:** شاشة العميل وشاشة الكابتن تعملان بتزامن لحظي.
- **تطبيق العميل:** تجربة المستخدم الكاملة من الطلب إلى التقييم والدفع.
- **تطبيق الكابتن:** تجربة استقبال الرحلة، تغيير الحالات، والأرباح.
- **لوحة تحكم الإدارة:** إدارة العمليات، الأسعار، الكباتن، والفحوصات الآلية.

### 2. الفحص والبناء للإنتاج:
```bash
# فحص الأنواع والتأكد من خلو المشروع من الأخطاء
npm run lint

# البناء النهائي لحزم الإنتاج
npm run build
```

## 🧪 حزمة الفحوصات والتشخيص التلقائي | Automated Diagnostic Suite
تم تضمين **22 فحصاً برمجياً واختباراً شاملاً** داخل لوحة الإدارة (تبويب "فحص واختبارات المحركات"):
- **سيناريوهات الرحلات (Scenarios A through J):**
  - **Scenario A:** رحلة سيارة كاملة (Passenger + Car).
  - **Scenario B:** رحلة دراجة نارية مع الحد الأدنى 700 ر.ي وعمولة 10% (Passenger + Motorcycle).
  - **Scenario C:** عدم توفر سائق متاح وتفادي الانهيار (No Driver Available).
  - **Scenario D:** إلغاء الرحلة من قبل الراكب (Passenger Cancellation).
  - **Scenario E:** إلغاء الرحلة من قبل السائق (Driver Cancellation).
  - **Scenario F:** فشل الدفع لنقص الرصيد (Payment Failure).
  - **Scenario G:** الدفع النقدي الناجح (Successful Cash Payment).
  - **Scenario H:** الدفع بالمحفظة وتسجيل الحركات في دفتر الأستاذ (Wallet Ledger).
  - **Scenario I:** منع القفزات غير المشروعة في دورة حياة الرحلة (Invalid State Transitions).
  - **Scenario J:** استبعاد السائق المشغول من التوزيع (Driver Already Busy).
- **قواعد التسعير الرسمية:** الحد الأدنى للسيارة 1,800 ريال، الدراجة 700 ريال، عمولة 10%.
- **محرك المسافات (Haversine):** دقة حساب المسافات الجغرافية في صنعاء.
- **أرقام مزودي الاتصالات اليمنية:** التحقق من شبكات 77، 73، 71، 78، ومنع الهجمات المتكررة على OTP.
- **عزل البيانات والصلاحيات:** منع وصول الركاب أو السائقين إلى صلاحيات الإدارة، وعزل بيانات الركاب.
