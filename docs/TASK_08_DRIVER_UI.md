# MISHWAR — TASK 08 Driver App Final UX

## النتيجة المختصرة

تم تنفيذ TASK 08 داخل تطبيق الكابتن فقط، بدون تعديل Backend أو Ledger أو Firebase أو إعدادات السحابة.

حالة المهمة: PASS للتشغيل المحلي والتحليل والاختبار المتاح.

## الملفات المعدلة

- `apps/driver_app/lib/main.dart`
- `docs/TASK_08_DRIVER_UI.md`

## ما تمت مراجعته

- شاشة الدخول والتسجيل: موجودة عبر `AuthGate` و`PhoneOtpSignIn` من `mishwar_shared/mobile_runtime.dart`.
- بيانات الكابتن والمركبة: تم تنظيمها في بطاقة حساب الكابتن داخل تبويب "حسابي".
- KYC ورفع الوثائق: موجودة وتم إبقاؤها خلف وضع غير Demo حتى لا تختلط بيانات الاختبار مع Pilot.
- حالة متاح/غير متاح: موجودة في AppBar مع تعطيلها أثناء الرحلة النشطة.
- استقبال الرحلات السريعة: يعتمد على `incomingRide` و`rideAction('accept'/'decline')`.
- استقبال مشوار بالعروض: يعتمد على `submitRideBid`.
- سحب عرض السعر: تمت إضافته في واجهة الكابتن باستخدام `withdrawRideBid` الموجود مسبقاً.
- قبول/رفض الرحلة: موجود داخل بطاقة الرحلة.
- عرض مسار الوصول للعميل: موجود عبر `MishwarMap` عند تفعيل routing، مع Placeholder ثابت للاختبارات.
- بدء وإنهاء الرحلة: موجود عبر إجراءات الحالة الحالية.
- تأكيد استلام الأجرة النقدية: موجود عند اكتمال رحلة CASH غير مدفوعة.
- حسابي المالي: موجود وتم نقله إلى تبويب مستقل مع عمولة 10% والمديونية والتسويات.
- سجل الرحلات: أضيف تبويب يعرض آخر رحلة/فاتورة تشغيلية متاحة من Backend.
- التقييمات والإشعارات: الإشعارات مدعومة عبر تسجيل FCM الحالي، والتقييمات تحتاج Endpoint/بيانات حقيقية لاحقاً.
- المساعدة والطوارئ: أضيفت بطاقة دعم ومراجعة حساب وعن التطبيق، مع بقاء SOS داخل الرحلة.
- ضعف الإنترنت والأخطاء: بقيت رسائل الأخطاء و`OfflineSyncCard` وواجهة إعادة محاولة الموقع.
- RTL والعربية: التطبيق مضبوط على `ar_YE` وتم تنظيم التبويبات والنصوص بالعربية.

## التغييرات المنفذة

- إعادة بناء شاشة الكابتن إلى تبويبات:
  - الرئيسية
  - الرحلات
  - المالية
  - حسابي
- إضافة لوحة تشغيل للكابتن تعرض:
  - حالة متاح/غير متاح
  - نوع الطلب FAST أو BIDDING
  - المديونية الحالية
  - حالة الرحلة
- إضافة Placeholder ثابت للخريطة عند تعطيل routing في الاختبارات، لمنع اعتماد الاختبار على خرائط خارجية.
- إضافة تتبع محلي لعرض السعر المرسل حتى يستطيع الكابتن سحبه من الواجهة.
- الحفاظ على كل استدعاءات الرحلات والمالية عبر APIs الحالية فقط.
